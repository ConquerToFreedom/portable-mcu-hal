## Bugs found while building this suite

`../uart/hal_port_nrf52_uart.c` calls `nrfx_uarte_init()` without the explicit context argument
this vendor's I2C/SPI adapters both pass, so its event handler's
`(hf_uart_t)(uintptr_t)p_context` cast has no reliable way to identify which UARTE instance fired
— see `fakes/nrfx_uarte.h`'s header comment. This test suite therefore only exercises UARTE
instance 0; verify against a real nrfx build before relying on UARTE1 in production.

`../pwm/hal_port_nrf52_pwm.c` used `NRFX_PWM_DEFAULT_CONFIG_IRQ_PRIORITY`, assumed during PWM's
design pass to be a real nrfx default macro — it isn't. Caught immediately once `fakes/nrfx_pwm.h`
(correctly) didn't define it and the build failed; fixed in the adapter with a project-defined
`HF_NRF52_PWM_IRQ_PRIORITY` constant instead, the same pattern `hal_port_nrf52_timer.c` already
uses for its own IRQ priority.

## What's covered (typical pattern, not every file has all of these)

- Valid instance/channel → success; invalid instance/channel → `false`, no crash.
- Blocking call: correct nrfx calls made, correct data in/out.
- Async call: registered callback does **not** fire until the simulated event fires; fires
  exactly once when it does, with the right value/success flag.
- A second async call while one is already in flight is rejected (SPI, UART — not I2C, whose
  adapter has no such guard, see the file itself).
- An error/NACK event clears the busy flag but does **not** invoke the callback where this
  vendor's event model supports reporting one (I2C's NACK; SPIM has only one event type and no
  failure signal).
