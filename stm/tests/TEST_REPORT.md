## What's covered (typical pattern, not every file has all of these)

- Valid instance/channel → success; invalid instance/channel → `false`, no crash.
- Blocking call: correct HAL calls made, correct data in/out.
- Async call: registered callback does **not** fire until the simulated ISR fires (`HAL_*Cplt
  Callback`/`HAL_*ErrorCallback` called directly); fires exactly once when it does, with the
  right value/success flag.
- A second async call while one is already in flight is rejected.
- An error callback clears the busy flag but does **not** invoke the registered callback (the
  "no false success" rule from `docs/architecture.md`).

## Known limitations

See `README.md`'s "Known limitations" section — host x86-64 (not real ARM), fakes hand-written
against research notes rather than a real installed SDK, and the busy-flag test-isolation trap.
`test_flash.c`'s read test also needs a `MAP_32BIT` mapping to safely exercise `hf_flash_read()`'s
raw pointer dereference on this 64-bit host — see `nrf/tests/TEST_REPORT.md` for why.
