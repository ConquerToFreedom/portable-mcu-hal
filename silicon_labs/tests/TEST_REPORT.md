## Notable findings while building the Timer/PWM tests

The classic PWM adapter's `GPIO->TIMERROUTE`/`ROUTEEN` pin-routing register
code (see `../pwm/hal_port_silabs_pwm.c`'s own header comment) needed a
genuinely new fake — a `GPIO` peripheral-level struct that didn't exist
anywhere in this vendor's fakes before — and its tests (`test_silabs_pwm.c`)
directly verify the route value and the enable bit, not just that
`hf_pwm_start()`/`set_duty()` return `true`. One real fake limitation
surfaced and is documented in `fakes/silabs/em_timer.h`: Silicon Labs' real
`_SET` register alias has OR semantics in hardware, which this fake's plain
struct field can't reproduce — no current test depends on it.

The current-SDK Timer test suite includes a regression check
(`test_init_calls_sl_sleeptimer_init`) tied directly to the earlier bug
where `hal_port_silabs_slgpio_timer.c` never called `sl_sleeptimer_init()`
at all (see `docs/architecture.md`'s Silicon Labs clock-enable bug-fix
section) — it confirms the adapter actually calls it, not just that it
compiles against a header that declares it.

## Notable findings while building the Flash tests

The current-SDK (`TARGET_SILABS_SLGPIO`) Flash adapter uses the exact same `em_msc.h` calls as
the classic adapter — there is no distinct current-generation driver at this level, unlike
GPIO/I2C/ADC's real `sl_gpio`/`sl_i2c`/IADC layers or even PWM's thin `sl_pwm` convenience driver
(see `hal_port_silabs_slgpio_flash.c`'s own header comment). Both targets' `test_silabs*_flash.c`
files are therefore intentionally near-identical, run against their own adapter file.

`hf_flash_read()`'s raw-pointer `memcpy` segfaulted the first time its test ran, for the same
reason noted in `nrf/tests/TEST_REPORT.md` — fixed the same way (a `mmap(..., MAP_32BIT, ...)`
mapping in the test itself).

While extending `silicon_labs/footprint/generate_report.sh` for this adapter, found that its
summary table's two `for f in build/gpio.o ...` loops hardcoded only GPIO/UART/I2C/SPI/ADC —
Timer and PWM (added in an earlier pass) were silently missing from the table and the `.text`
total, though still shown correctly in the "Largest functions" section below it. Fixed to include
Timer/PWM/Flash in both loops; see the regenerated `FOOTPRINT.md`.

## What's covered (typical pattern, not every file has all of these)

- Valid instance/channel → success; invalid instance/channel → `false`, no crash.
- Blocking call: correct vendor calls made, correct data in/out.
- Async call: registered callback does **not** fire until the simulated interrupt/event fires;
  fires exactly once when it does, with the right value/success flag.
- A second async call while one is already in flight is rejected.
- An error/NACK event or failure status clears the busy flag but does **not** invoke the
  callback (the "no false success" rule from `docs/architecture.md`), where this vendor's event
  model reports one.
