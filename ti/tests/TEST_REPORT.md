## What's covered (typical pattern, not every file has all of these)

- Valid instance/channel → success; invalid instance/channel → `false`, no crash.
- Blocking call: correct driverlib calls made, correct data in/out.
- Async call: registered callback does **not** fire until the simulated IRQ handler is invoked;
  fires exactly once when it does, with the right value.
- A second async call while one is already in flight is rejected.
- GPIO's documented, permanent limitation is covered directly: `hf_gpio_init()` returns `false`
  for pull-up/pull-down/open-drain modes, since those live in IOMUX PINCM, unreachable from
  `hf_gpio_t` alone.

## Known limitations

See `README.md`'s "Known limitations" section — host x86-64 (not real ARM), fakes hand-written
against research notes rather than a real installed SDK (including some constant names the
adapters themselves flag as unconfirmed), and the busy-flag test-isolation trap.
`test_flash.c`'s read test also needs a `MAP_32BIT` mapping to safely exercise `hf_flash_read()`'s
raw pointer dereference on this 64-bit host — see `nrf/tests/TEST_REPORT.md` for why.
