# TI MSPM0 adapter flash/RAM footprint

Generated by `make -C ti/footprint report` against a real ARM cross-compiler
(`GNU size (2.42-1ubuntu1+23) 2.42`), `-mcpu=cortex-m0plus -Os`. Each adapter `.c` file
is compiled standalone to a `.o` (never linked into a full firmware image - no
vendor SDK is installed in this environment) against the same fake TI driverlib
header `../tests/fakes/` uses for unit testing, since compiling only needs
declarations, not its behavioral body. See "What these numbers do and don't
mean" below before quoting one out of context.

Sum of all 8 adapters' `.text`: **3428 bytes** - a real project only
ever includes the peripherals it actually uses, so treat this as a ceiling, not
a typical build. Useful as a regression baseline: re-run after changing an
adapter and diff against a committed copy of this file.

## What these numbers do and don't mean

- **Real compiler, real target ISA (Cortex-M0+), real -Os.** This is genuinely
  how much flash each adapter's code costs - not a host-machine proxy.
- **No vendor SDK is linked in.** Every `HAL_*` call the adapter makes resolves
  to an external symbol with zero bytes charged here - the real TI driverlib's own
  flash cost is NOT included. These numbers are the wrapper adapter's *own* code
  only, the same scope this project's contract covers.
- **No linker garbage collection was run** (`--gc-sections` needs a full link),
  so a function only reachable from an unused code path (e.g. the async tier, if
  your project only calls the blocking one) is still counted here - real
  firmware with `--gc-sections` enabled would drop it.
- **.bss (RAM) is per-adapter static state** (ring buffers, busy flags, callback
  pointers) - real total RAM also depends on your linker script and whatever
  else runs on the same part.
